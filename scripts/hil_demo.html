AutoQrypt™ System Architecture & Cryptographic Threat Model

The Automotive Security Problem (PQC-02)

Connected autonomous vehicles rely on Over-The-Air (OTA) updates to patch safety-critical ECUs (Brakes, BMS, Powertrain, ADAS). Modern quantum computers will break classical asymmetric cryptography (RSA, ECDSA, Ed25519) via Shor's algorithm. Adversaries can record encrypted OTA broadcasts today (Harvest-Now-Decrypt-Later) or deploy compromised Director servers to flash backdoored or downgraded firmware.

Threat 1: Quantum Key Forgery
Adversaries forge signatures of legitimate OEMs.
Mitigation: NIST FIPS 204 ML-DSA-44 lattice mathematics resistant to quantum cryptanalysis.
Threat 2: Director Server Compromise
A compromised cloud server tries to push arbitrary code.
Mitigation: Uptane 2-Role split: Online Director cannot sign without Offline OEM Root key.
Threat 3: Downgrade Replay Attack
Attacker replays a genuine but vulnerable old firmware.
Mitigation: Physical hardware NVS monotonic version counter fails closed on any rollback.
Threat 4: In-Flight Bus Bit-Flips
CAN-FD transmission corruption or malicious MITM bit-flips.
Mitigation: 4,096-byte chunked streaming with incremental SHA3-256 absorption and inactive slot staging.
Hardware-in-the-Loop (HIL) Silicon Execution Target

This operations console communicates directly with an Espressif ESP32-WROOM-32 microcontroller (Xtensa Dual-Core LX6 @ 240 MHz, 520 KB SRAM, 4 MB Flash) communicating via UART CAN-FD at 921,600 Baud. All timing latencies (Falcon: ~4.9 ms, ML-DSA: ~17.7 ms, Ed25519: ~34.0 ms) are measured directly on physical silicon via hardware cycle counters.
